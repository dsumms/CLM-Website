    Here is a frontend audit of the CLM site. I focused on what hurts users, what hurts performance, and what is broken.



    THE BIG PICTURE

    The site is a Next.js 16 app with a heavy 3D Gaussian splat hero, CSS modules, and Framer Motion scroll animations. It looks cinematic, but the architecture has drifted toward "client-side React app" instead of leveraging what Next.js does well. Several pages are missing, the navigation is inverted on desktop, and the 3D hero is over-engineered for a film company portfolio.



    CRITICAL FIXES

    1. Missing pages will 404
    Your Navbar links to /work, /process, /about, and /contact. Only /about exists. Either build the missing pages or change the Navbar to anchor links (#work) and a mailto for Contact until the pages are ready.

    2. Desktop navigation is hidden by default
    Your Navbar renders isOpen && !isMobile, meaning on desktop the links are invisible until someone clicks the hamburger. That is mobile behavior forced onto desktop. Flip the logic: show the train-car links by default on desktop, hide them behind the hamburger only on mobile.

    3. Empty team photos on the About page
    teamPhoto divs have no source. Empty gray circles look like a bug. Either add headshots or remove the circles entirely and stack the text cleanly until you have assets.

    4. Broken project thumbnail fallback
    ProjectCard uses https://img.youtube.com/vi/${youtubeId}/maxresdefault.jpg. Not every video has a maxresdefault.jpg. YouTube returns a 404, and the user sees a broken image icon. Fallback to hqdefault.jpg or verify the ID exists.



    PERFORMANCE & ARCHITECTURE

    5. Stop making entire pages client components
    page.tsx and about/page.tsx are both "use client". This kills static generation and sends a fat JS bundle before the user sees anything.

    - Home page: The only reason it is client-side is the mounted check for SplatHero. Move SplatHero into its own client island and keep the rest of the page server-rendered.
    - About page: It uses useScroll and useTransform for parallax. Either wrap only the parallax image blocks in a client component, or replace Framer Motion scroll with CSS scroll-driven animations (now supported in Chromium) to keep it server-rendered.

    6. The 3D splat hero is massive overkill
    SplatHero.tsx is ~20KB of source before minification. It includes debug overlays, calibration modes, wiggle configs, and URL flags. For a production portfolio, strip this down to the render call and fallback logic, or replace it with a high-quality static image / video loop. Gaussian splat files are often 10MB+. On mobile that is unacceptable load.

    7. YouTube thumbs bypass Next.js Image
    ProjectCard uses a raw <motion.img> for YouTube thumbnails. Use next/image with unoptimized if you must, or proxy the thumbs through your own API route. At minimum, add loading="lazy" and sizes so the browser does not fetch full-resolution images for every card on load.

    8. Remove Tailwind if you are not using it
    You have Tailwind v4 and @tailwindcss/postcss in package.json, but every style is in CSS modules. Either adopt Tailwind for utilities (recommended) or remove it to cut dead weight from node_modules and build time.

    9. width: 100vw causes horizontal overflow
    In page.module.css and globals.css, 100vw includes the scrollbar gutter on Windows. Change to width: 100% or max-width: 100%. The overflow-x: hidden on body is just hiding the symptom.



    MOBILE & ACCESSIBILITY

    10. No reduced-motion support
    Your parallax, scroll-triggered fades, and logo marquee run even for users with prefers-reduced-motion: reduce. Wrap Framer Motion animations with useReducedMotion() and disable the CSS marquee animation for those users.

    11. Partner logo marquee lacks pause
    Infinite scrolling content should pause on hover/focus so users can read it. Add animation-play-state: paused on hover.

    12. Weak alt text and missing ARIA
    - Partner logos all say alt="Partner Logo". Use the actual org name.
    - The play button overlay is an empty div with no aria-label.
    - The mobile menu is a motion.div with no role="dialog" or focus trap.

    13. Small tap targets
    The train-car menu links on tablet are dense. Make sure mobile menu items have at least 44px touch height.



    VISUAL POLISH

    14. Pure black is harsh
    #000000 backgrounds feel flat on OLED and dated. A slightly warmer near-black like #050505 or #080807 gives depth without losing contrast.

    15. Hero text shadow is too heavy
    text-shadow: 0 4px 20px rgba(0,0,0,0.9), 0 0 50px... on white text over a dark background creates muddy halos. Lighten or remove the shadow; the splat/image behind is already dark.

    16. Accent color is underused
    #ff4500 appears only on play-button hover. If "chili" is part of the brand, use the accent for active nav states, link underlines, or section dividers so it reads as intentional rather than accidental.



    BOTTOM LINE / PRIORITY ORDER

    If you want the biggest impact for the least effort:

    1. Fix Navbar desktop visibility (invert isOpen logic).
    2. Remove "use client" from pages; isolate it to SplatHero and parallax wrappers only.
    3. Add placeholder or remove empty teamPhoto divs.
    4. Swap maxresdefault.jpg for hqdefault.jpg with an onError fallback.
    5. Add prefers-reduced-motion checks to all Framer Motion components.
    6. Decide on Tailwind (adopt it or remove it).
    7. Audit the SplatHero bundle size; consider a static hero image for mobile.
